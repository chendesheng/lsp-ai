# Explain and fix diagnostics

Enable dynamic diagnostic actions in `initializationOptions`:

```json
{
  "diagnostic_actions": {
    "model": "model1",
    "parameters": {
      "max_context": 4096,
      "max_tokens": 1024,
      "temperature": 0
    },
    "explanation_severity": 1
  }
}
```

`model` is a key in the existing `models` configuration and must refer to an
instruction model. Diagnostic actions are disabled when this section is omitted.
The feature builds its own prompts and response format; do not supply completion
messages, FIM markers or completion post-processing in this section.

The action list is generated from the `context.diagnostics` sent by the editor
with `textDocument/codeAction`. Each error produces `Explain: <message>` and
`Fix: <message>`. Warnings and diagnostics generated by LSP-AI are excluded.
There is no model request while listing actions. The diagnostic range, source,
code and message are retained, so two errors at the same location can be handled
independently. Errors with identical diagnostic contents are deduplicated.

Explain requests one short sentence of at most 30 words, stating only the cause.
Its output is capped at 128 tokens even if `parameters.max_tokens` is larger. Fix
actions retain the configured output limit.

Selecting **Explain** calls the model and publishes the response as an additional
diagnostic at the original range, with source `lsp-ai`. Other language servers'
diagnostics remain owned by those servers. Explanations for other errors in the
same file are retained; explaining an error again replaces its previous response.
Explanations are cleared on document changes, close or rename. Helix controls
ordering within the diagnostic stack; an explanation is not guaranteed to appear
immediately below its original error.

`explanation_severity` uses LSP values: 1 = error (default), 2 = warning,
3 = information, 4 = hint. Error severity works with an errors-only display but
also contributes to the editor's error count. Set it to 3 and enable information
diagnostics if you prefer explanations not to count as errors.

Selecting **Fix** calls the model and returns a versioned `WorkspaceEdit` for the
current file. The model returns exact search/replacement snippets. Missing,
ambiguous, empty, overlapping and unchanged replacements are rejected. Multiple
edits, including insertions expressed as replacements of surrounding snippets,
are supported. The editor applies the edit; the normal language server then
checks the new code. AI fixes are proposals, not proof that the error is solved.

Requests are rejected with `ContentModified` if the document changed after the
action was listed or while the model was responding. Explanations are not written
to the file. Fixes do not edit other files. Context is bounded to approximately
`max_context * 4` characters around the diagnostic, so a distant declaration or
other-file dependency may require a manual change.

## Helix

Keep the normal language server and add `diagnostics` to LSP-AI's enabled features:

```toml
[language-server.lsp-ai.config.diagnostic_actions]
model = "model1"
explanation_severity = 1

[language-server.lsp-ai.config.diagnostic_actions.parameters]
max_context = 4096
max_tokens = 1024
temperature = 0.0

[[language]]
name = "typescript"
language-servers = [
  "typescript-language-server",
  { name = "lsp-ai", only-features = ["completion", "code-action", "diagnostics"] },
]
```

With the cursor on an error, press `Space a` and choose `Explain: ...` or `Fix: ...`.
For example, to display explanations beneath the cursor line:

```toml
[editor.inline-diagnostics]
cursor-line = "error"
other-lines = "disable"
```

The client must include diagnostics from the normal language server in the action
request. Helix does so for diagnostics overlapping the primary selection. If the
request contains no errors, LSP-AI offers no diagnostic actions.

## Offline validation

```sh
cargo test -p lsp-ai --bin lsp-ai diagnostic_actions --no-default-features --features rayon
cargo build -p lsp-ai --no-default-features --features rayon
python3 crates/lsp-ai/tests/diagnostic_actions_protocol.py target/debug/lsp-ai
python3 crates/lsp-ai/tests/diagnostic_actions_protocol.py target/debug/lsp-ai --disabled
```

The protocol test starts a local mock OpenAI-compatible server; it requires no API
key, paid model or external service.
